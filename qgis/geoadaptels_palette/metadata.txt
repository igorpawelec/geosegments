about=QGIS Processing provider wrapping the pygeoadaptels and pygeopalette Python packages: adaptels, SICLE, seeded region growing (grow_seeds), connectivity enforcement, vectorization, and 15 colour-space conversions. The algorithms stay in the packages; this plugin is glue. Both packages are bundled inside the plugin, so they need no download; numba, rasterio and fiona are installed into the plugin's own libs folder on first run.

changelog=0.5.11 -- bundles pygeoadaptels 0.10.6: the compute kernels no longer hold Python's global interpreter lock while they run, so other Python code in QGIS is not stopped for the length of a segmentation. The results are bit-identical. The first run after the update compiles the kernels again.
    0.5.10 -- bundles pygeopalette 0.8.0: the bands of a converted raster carry the names of their components (L, a, b for CIELAB), so the layer lists them by name where it listed Band 1 to Band 3. The values are unchanged.
    0.5.9 -- two runs at the same time, or a run of this plugin and one of GeoSnag, no longer leave the rasterio and fiona loggers switched off for the rest of the session. The guard against the 'Logging error' traceback, new in 0.5.8, saved and restored the loggers per run; it now counts the runs. No change in the tools.
    0.5.8 -- results are styled again: on QGIS 4 the label palette, the crown outlines and the colour-space stretch were lost and every result loaded with QGIS's default style. A mistake in the input (a threshold on the wrong scale, a point outside the raster, a one-band raster for a colour space, an output folder that does not exist) is reported as a message, not as a Python traceback; the traceback goes to the Log Messages panel. The help texts are readable in dark themes. A warning that GDAL passes to rasterio no longer prints a 'Logging error' traceback into the Python console when another plugin has left the root logger without a stream. The Grow seeds dialog opens with max_cost 15 and max_radius 20; with both fields emptied every pixel is given to one of the points, and a script that leaves the two out is not affected. Enforce connectivity keeps a negative nodata value of its input (-1 from SICLE and Grow seeds) instead of declaring -9999 over it. Bundles pygeoadaptels 0.10.5: the SICLE raster declares the nodata value it holds (-1), and area_m2 and perimeter of the vectorised polygons are measured on each polygon, which changes their values. The copy of numpy that pip leaves in the plugin's libs folder, about 54 MB that QGIS never reads, is removed.
    0.5.7 -- a new icon: a Q around the segments of the geosegments mark, three of them in the colours of the geopalette bands, drawn from a vector source. No change in the algorithms.
    0.5.6 -- the plugin lives in github.com/igorpawelec/geosegments, next to the pygeoadaptels package it bundles; the homepage, the tracker and the link to the grow seeds guide name the new address. No change in the algorithms.
    0.5.5 -- no post-processor reads a raster any more: the label palette is built from the label count the algorithm already has and the colour-space stretch from band ranges measured in the worker, so the on_complete access violation a statistics pass on the GUI thread could trigger (0.2.1-0.5.4, found in GeoSnag) is gone; the binary dependencies install into the plugin's own libs/ folder instead of the user site, which every Python 3.12 on the machine reads (pip --user had broken a conda environment); a zip reinstall drops the previously imported vendored modules; the post-processor is no longer kept alive after QGIS took ownership of it.
    0.5.4 -- declares qgisMaximumVersion 4.99 and supportsQt6, so QGIS 4 no longer lists the plugin as incompatible (designed for 3.28-3.99) at the next start; no code change.
    0.5.3 -- bundles pygeoadaptels 0.10.4: grow_seeds(fill_holes=True) no longer takes hours on a large orthophoto (pocket census in O(pixels), bit-identical labels).
    0.5.2 -- bundles pygeoadaptels 0.10.3: Enforce Connectivity with a minimum fragment size is about a hundred times faster (551 s to 5.4 s on a full-orthophoto window) with a bit-identical result.
    0.5.1 -- band selection actually works: the packages were writing their output in the input format, so the VRT that carries a band selection made them fail. Bundles pygeoadaptels 0.10.2 and pygeopalette 0.7.1.
    0.5.0 -- you choose which band is which. Colour conversion takes explicit red, green and blue band numbers instead of assuming 1/2/3, which was wrong for every CIR and NRGB raster; the segmentations take an optional band selection, empty meaning all. Bundles pygeoadaptels 0.10.1, which vectorises to GeoPackage about twelve times faster.
    0.4.3 -- the compute kernels are compiled on the main thread before the run starts. Installing the plugin from a zip wipes numba's compiled cache, and recompiling it on the worker thread took QGIS down; the first run after an update now pauses briefly instead.
    0.4.2 -- fixed a crash when styling the result of a large segmentation: the label-count check scanned every pixel on the GUI thread while the task was closing down. Styling now decides from the raster size, and never attaches itself to an output QGIS is not loading.
    0.4.1 -- plugin icon in the Plugin Manager, provider named GeoAdaptels + GeoPalette, metadata points at the plugin's own repository.
    0.4.0 -- renamed to match the renamed packages; packages bundled in the zip.
    0.3.0 -- the two pure-Python packages ship inside the plugin: no git, no download for them.
    0.2.2 -- label rasters get contrasting colours instead of an all-black palette.
    0.2.1 -- fixed a phantom output that made QGIS report a missing layer.
    0.2.0 -- styled results, advanced parameters collapsed, help with the dead-tree recipe.
    0.1.1 -- dependency bootstrap resolves QGIS's real interpreter.
    0.1.0 -- first release: six algorithms in the Processing toolbox.
